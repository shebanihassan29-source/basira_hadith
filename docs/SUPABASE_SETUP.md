# إعداد Supabase للإصدار الإنتاجي

## 1) إنشاء المشروع
أنشئ مشروعًا جديدًا في Supabase، ثم افتح **SQL Editor**.

## 2) تنفيذ المخطط
نفّذ أولًا:
- `docs/DATABASE_SCHEMA.sql`

ثم نفّذ:
- `supabase/migrations/0001_security_and_roles.sql`

بهذا يصبح لدينا الجداول الأساسية، الحسابات، الأدوار، RLS، وسجل تدقيق قابل للتوسعة.

## 3) إنشاء أول مستخدم
أنشئ المستخدم من **Authentication → Users**. بعد ذلك أضف صفًا له في `profiles` باستخدام معرف المستخدم (UUID).

> لا تضع مفتاح Service Role في الواجهة أو GitHub Pages.

## 4) الأدوار
الأدوار المعتمدة:
- مدير: إدارة المستخدمين والبيانات.
- باحث: إدخال المصادر والأحاديث والرواة.
- مراجع علمي: تنفيذ المراجعة واعتماد المرحلة العلمية.
- محرر: تحرير البيانات البحثية.
- قارئ: القراءة والاستعلام فقط.

هذه الصلاحيات هي طبقة أولية، ويجب اختبارها على بيانات تجريبية قبل الإنتاج.

## 5) Storage
أنشئ Bucket خاصًا مثل:
`hadith-sources`

الملفات الأصلية للكتب والوثائق تُخزن في Storage، بينما تحفظ قاعدة البيانات مسار الملف وبيانات المصدر.

## 6) مفاتيح الاتصال
الواجهة العامة يمكنها استخدام:
- Project URL
- anon/public key

مع تفعيل RLS دائمًا.

أما:
- Service Role Key

فيبقى على خادم آمن أو Edge Function ولا يوضع في `app.js` ولا في مستودع GitHub.

## 7) انتقال بصيرة الحديث
الإصدار الحالي سيستمر في العمل محليًا حتى يتم توفير بيانات المشروع. بعد ذلك نضيف طبقة API/Supabase تدريجيًا مع إبقاء النسخ الاحتياطي المحلي كخطة استرداد.

## 8) الاختبار قبل الإنتاج
اختبر على الأقل:
1. قارئ لا يستطيع الإدخال أو الحذف.
2. باحث يستطيع إنشاء مصدر وحديث.
3. مراجع علمي يستطيع تنفيذ المراجعة.
4. المدير يستطيع إدارة المستخدمين.
5. سجل التدقيق لا يقبل تعديلات مباشرة من العميل.
