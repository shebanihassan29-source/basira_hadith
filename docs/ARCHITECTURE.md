# معمارية بصيرة الحديث

## الوضع الحالي
واجهة static تعمل على GitHub Pages مع LocalStorage. GitHub Pages ينشر HTML/CSS/JavaScript الثابت، وليس خادمًا خلفيًا لقاعدة بيانات مشتركة.

## المعمارية المستهدفة
المستخدم ← واجهة بصيرة الحديث ← المصادقة والبحث وإدارة المصادر والأحاديث ← Supabase/PostgreSQL ← Storage للكتب + API للخدمات الخلفية.

الجداول الأساسية: sources, hadiths, narrators, hadith_narrators, scholar_judgments, hadith_variants, reviews, audit_logs.

## القواعد العلمية
1. النص الأصلي لا يُستبدل بناتج الذكاء الاصطناعي.
2. كل إحالة تحتوي على المصدر والموضع قدر الإمكان.
3. أحكام العلماء تحفظ مستقلة ومنسوبة إلى أصحابها.
4. المطابقة والبحث الدلالي أدوات مساعدة وليست حكمًا حديثيًا.
5. سجل التدقيق يحفظ من غيّر ماذا ومتى.
6. إجابات RAG يجب أن تستند إلى سجلات موثقة وتعرض إحالاتها.

## مراحل التنفيذ
A. الواجهة: المصادر، الأحاديث، المراجعة، الإحصاءات، الفهرس، النسخ الاحتياطي والاستيراد.
B. قاعدة البيانات: استخدام DATABASE_SCHEMA.sql.
C. الهوية والصلاحيات: مدير، باحث، مراجع علمي، محرر، قارئ.
D. الملفات: PDF/TXT/XML/JSON في Storage مع ربطها بالمصادر والطبعات.
E. الاستيراد: رفع → استخراج → OCR عند الحاجة → حفظ الأصل → تقسيم → مراجعة بشرية.
F. البحث: لفظي + تطبيع مساعد + دلالي مع إبقاء الأصل.
G. الروايات والأسانيد: ربط الطرق والرواة والمواضع دون افتراض صحة آلي.
H. RAG: الإجابة من المقاطع المسترجعة مع الإحالات.
I. التدقيق والنشر: انتقال «منشور» عبر صلاحية ومراجعة واضحة.

## القرار المعماري
GitHub Pages يبقى واجهة النشر العامة. قاعدة البيانات والملفات والمصادقة وخدمات الذكاء الاصطناعي تكون خارج Pages عبر API آمن.
