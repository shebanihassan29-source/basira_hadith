# 📚 بصيرة الحديث

منصة حديثية أكاديمية لإدارة المصادر والسجلات الحديثية والمراجعة العلمية، مع مسار مستقبلي للبحث الموجّه بالمصادر (RAG) والذكاء الاصطناعي المساعد.

## الإصدار
**v2.0 — Academic Research Workflow + Production Foundation**

### الوظائف الحالية
- لوحة متابعة وإحصاءات وصفية.
- مركز مصادر وبيانات ببليوغرافية.
- ربط الأحاديث بالمصادر.
- حفظ النص الأصلي مستقلًا عن السند والمتن والحقول التحليلية.
- بحث وفهرسة.
- مراجعة: مراجعة → موثق → منشور.
- سجل انتقالات لكل حديث.
- سجل الرواة وأحكام العلماء وتعدد الروايات.
- سجل تدقيق محلي للعمليات المهمة.
- مخطط PostgreSQL/Supabase وأدوار وصلاحيات أولية مع RLS.
- فحص تلقائي لصحة JavaScript والملفات الأساسية عبر GitHub Actions.
- نافذة تفصيل الحديث والمصدر.
- تصدير JSON للنسخ الاحتياطي.
- وضع ليلي وطباعة وتصميم متجاوب.
- PWA manifest وSEO أساسي.

## الضابط العلمي
لا تصدر المنصة حكمًا حديثيًا نهائيًا آليًا. أي حكم منسوب لعالم يجب أن يُحفظ مع مصدره وموضعه. التشابه النصي أو اقتراح الذكاء الاصطناعي لا يُعامل بوصفه حكمًا علميًا.

## التخزين
الإصدار الحالي يستخدم LocalStorage، وهو مناسب للنموذج الأولي فقط. لا يُنصح باعتباره قاعدة بيانات إنتاجية مشتركة.

## خارطة الطريق
1. ربط الواجهة بـ Supabase مع طبقة بيانات قابلة للتراجع إلى LocalStorage.
2. Object Storage للملفات الأصلية.
3. API وصلاحيات المستخدمين.
4. استيراد PDF/TXT/XML/JSON مع OCR عند الحاجة.
5. فصل السند والمتن مع إبقاء الأصل.
6. مطابقة الروايات مع درجة تشابه تفسيرية لا حكمية.
7. إدارة الرواة والأسانيد.
8. تخزين أحكام العلماء مستقلة ومسنودة بالمراجع.
9. RAG مؤسس على مصادر موثقة مع إحالات.
10. سجل تدقيق خادمي كامل ونسخ بيانات.

### ملفات البنية الإنتاجية
- `supabase/migrations/0001_security_and_roles.sql` للصلاحيات وRLS والتحديثات الآلية.
- `docs/SUPABASE_SETUP.md` لدليل الإعداد الآمن.
- `.github/workflows/validate.yml` للتحقق الآلي من سلامة الإصدار.

## هندسة الإصدار الإنتاجي
أضيف إلى المشروع مخطط قاعدة بيانات PostgreSQL/Supabase في `docs/DATABASE_SCHEMA.sql` ووثيقة المعمارية في `docs/ARCHITECTURE.md`. كما أضيفت صفحة 404 وملف `.nojekyll` لتحسين نشر GitHub Pages.

**تنبيه:** الإصدار المنشور حاليًا ما يزال يعمل محليًا عبر LocalStorage. لم يتم ربط قاعدة بيانات خارجية أو مفاتيح Supabase، لأن ذلك يتطلب إنشاء مشروع Backend فعلي وتحديد بيانات الاتصال والصلاحيات. GitHub Pages نفسه خدمة استضافة ملفات ثابتة، لذلك لا ينبغي وضع مفاتيح سرية أو منطق خادم فيها.
